# 通知

`.env` に Webhook URL を設定すると、インシデントの変化を Discord / Slack へ通知します。
どちらも Incoming Webhook を使うため、追加のパッケージやトークンは不要です。

通知するのは、前回の通知内容から変化したものだけです。

| 種類 | 通知するタイミング | 見出し |
| --- | --- | --- |
| 新規 | 前回の記録に無いインシデントを検出したとき | 🚨 新しいインシデント: インシデント名 |
| 更新 | 記録時から `updated_at` が変化したとき | 🔄 状況が更新されました: インシデント名 |
| 復旧 | 記録にあるインシデントが未解決一覧から消えたとき | ✅ 復旧しました: インシデント名 |

Discord へは Unicode の絵文字をそのまま送り、Slack へはショートコード
（`:rotating_light:` / `:arrows_counterclockwise:` / `:white_check_mark:`）で送ります。
表示される絵文字はどちらも同じです。

- 新規・更新は `impact` に応じて色分けします（`critical` = 赤、`major` = 橙、`minor` = 黄）
- 復旧は影響度に関わらず緑で通知します
- インシデント名から `shortlink` へリンクします（復旧時はリンク先が無いため付きません）
- 1 回の通知に含めるのは 10 件までです（Discord の embeds 上限に合わせています）。
  超過分は見出しに「他 N 件」と表示します
- 変化が 1 件も無いときは通知しません
- 片方の送信に失敗しても、もう片方の送信は継続します

復旧したインシデントは未解決一覧から消えるため、API からは影響度もコンポーネントも取得できません。
そのため復旧の通知には、前回通知した時点の記録（インシデント名・直前のステータス・前回の更新日時）を使います。

通知先の設定を確かめたいときは `-test-notify` でサンプルを送れます。
詳しくは [実行方法とテスト](usage.md#テスト通知) を参照してください。

## 重複通知の抑止

定期実行しても同じインシデントを繰り返し通知しないよう、通知済みのインシデントを
`./notified_incidents.json` に記録しています。

```json
{
    "incidents": {
        "cp306tmzcl0y": {
            "name": "Unplanned Database Outage",
            "status": "identified",
            "updated_at": "2014-05-14T14:35:21.711-06:00"
        }
    }
}
```

復旧を通知した後は、そのインシデントの記録を削除します。
未解決のものだけを残すため、ファイルが際限なく増えることはありません。
すべて通知し直したい場合は、このファイルを削除してください（未解決のインシデントが新規として通知されます）。

なお、送信に失敗した場合は記録を更新しないため、次回の実行で再送されます。

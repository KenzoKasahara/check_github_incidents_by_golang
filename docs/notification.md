# 通知

`.env` に Webhook URL を設定すると、インシデントの変化を Discord / Slack へ通知します。
どちらも Incoming Webhook を使うため、追加のパッケージやトークンは不要です。

通知するのは、前回の通知内容から変化したものだけです。

| 種類 | 通知するタイミング | 見出し |
| --- | --- | --- |
| 新規 | 前回の記録に無いインシデントを検出したとき | 🚨 新しいインシデント: インシデント名 |
| 更新 | 記録時から `updated_at` が変化したとき | 🔄 状況が更新されました: インシデント名 |
| 復旧 | インシデントが解決済みになったとき | ✅ 復旧しました: インシデント名 |

Discord へは Unicode の絵文字をそのまま送り、Slack へはショートコード
（`:rotating_light:` / `:arrows_counterclockwise:` / `:white_check_mark:`）で送ります。
表示される絵文字はどちらも同じです。

- 新規・更新は `impact` に応じて色分けします（`critical` = 赤、`major` = 橙、`minor` = 黄）
- 復旧は影響度に関わらず緑で通知します
- インシデント名から `shortlink` へリンクします
- 復旧の通知には、GitHub が投稿した最後のコメント本文を載せます（長い場合は 300 文字で切り詰めます）
- 1 回の通知に含めるのは 10 件までです（Discord の embeds 上限に合わせています）。
  超過分は見出しに「他 N 件」と表示します
- 変化が 1 件も無いときは通知しません
- 片方の送信に失敗しても、もう片方の送信は継続します

### 復旧の検出

復旧は次の 2 通りで検出します。

1. 前回の記録にあるインシデントが、未解決一覧（`unresolved.json`）から消えたとき
2. 過去のインシデント一覧（`incidents.json`）で `resolved`（または `postmortem`）になっているとき

1 だけでは、未解決の状態を一度も観測できなかったインシデントを取りこぼします。
実行間隔より短い障害や、ツールを止めていた間に始まって終わった障害がこれにあたります。
2 を併せて見ることで、そうした障害の復旧も通知します。

ただし過去のインシデント一覧には数日前の分も含まれるため、そのまま通知すると
毎回同じ内容が飛んでしまいます。そこで `notified_incidents.json` に
「前回どこまで確認したか」を記録し、それより後に解決したものだけを通知します。

- 初回実行時（記録が無いとき）は、過去の障害がまとめて飛ばないよう復旧を通知しません
- 記録する時刻には、実行するマシンの時計のずれに左右されないよう GitHub 側の時刻を使います

復旧の通知に載せる影響度・コンポーネント・発生日時・復旧日時・コメント本文は、
未解決一覧ではなく過去のインシデント一覧から取得します。
過去 50 件から漏れて取得できなかった場合だけ、前回通知した時点の記録
（インシデント名・直前のステータス・前回の更新日時）で代替します。

通知先の設定を確かめたいときは `-test-notify` でサンプルを送れます。
詳しくは [実行方法とテスト](usage.md#テスト通知) を参照してください。

## 重複通知の抑止

定期実行しても同じインシデントを繰り返し通知しないよう、通知済みのインシデントを
`./notified_incidents.json` に記録しています。

```json
{
    "incidents": {
        "cp306tmzcl0y": {
            "name": "Unplanned Database Outage",
            "status": "identified",
            "updated_at": "2014-05-14T14:35:21.711-06:00"
        }
    },
    "last_checked_at": "2026-08-31T13:54:08.001Z"
}
```

`last_checked_at` は前回どこまで確認したかを表す目印で、復旧の検出に使います。

復旧を通知した後は、そのインシデントの記録を削除します。
未解決のものだけを残すため、ファイルが際限なく増えることはありません。
すべて通知し直したい場合は、このファイルを削除してください
（未解決のインシデントが新規として通知されます。すでに解決した障害は通知されません）。

なお、送信に失敗した場合は記録を更新しないため、次回の実行で再送されます。
